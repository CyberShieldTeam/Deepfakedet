## Architecture and free-tier feasibility

Vercel serves the React/TypeScript/Vite static build. Its Build Output API routes `/api/*` to the actual Render backend origin before SPA fallback, without API caching. Express stays on Render because the application uses owned subprocesses, worker threads, SSE and a single-writer JSON repository. A separate Render web service runs a lean Python measurement/region/video/OCR-preparation profile. It requires a shared server-only token, while its non-sensitive health endpoint remains public.

Both Blueprint services explicitly use `plan: free`. There are no paid disks, databases, cron jobs or paid autoscaling. [Render free services](https://render.com/docs/free) sleep after15minutes without inbound traffic, can take about a minute to wake and lose local files on restart/redeploy/spindown. The workspace's750monthly free instance-hours are shared by the two services: two always-active services cannot both run for an entire month on that allowance. No keep-awake workaround is provided. Included bandwidth/build limits also apply. [Free hosting resources](https://render.com/pricing) provide512MB per service; Docker does not increase that budget.

Existing local models cannot be safely advertised on512MB: image/face loading requires2GiB free headroom; AASIST1GiB; NLI1.5GiB; reranking2.5GiB. Those are existing admission budgets, not measured universal minimums, and are preserved. No GPU is available on the selected free services. No trained video authenticity detector is validated. Full Torch/transformer environments and large checkpoints are intentionally absent from the lean image. This is an explicit profile limitation, not replacement inference.

| Engine/capability | Free-profile implementation | Remaining restriction |
|---|---|---|
| Image | Browser ELA/frequency measurements; protected Python signals/EXIF/C2PA; pinned YuNet face candidates | Trained whole-image and face-crop classifiers unavailable; no authenticity verdict |
| Audio | Browser decode/spectrum/segments and explicit unavailable AASIST stage | No Torch/AASIST inference; music/speech authenticity unvalidated |

| Network | Actual lexical/content/URL/time algorithms, clustering, graph and episode witnesses | No semantic embedding provider by default; no automatic malicious-intent claim |
| Correlation | Guest-owned cases, graph, timeline, signed evidence and reports | Temporary single-instance storage; anonymous review is session attribution, not verified identity |
| Gemini | Existing opt-in server API and schema safeguards preserved | Requires operator's free-tier key/quota and separate media sharing consent; not executed in deployment checks |

The public UI states these limits. Raw experimental observations never authorize validated real/fake or factual verdicts. Optional provider failure preserves uncertainty.

## Guest security and storage

`VERITAS_PUBLIC_GUESTS=1` explicitly enables automatic random HttpOnly/Secure/SameSiteStrict sessions. The bootstrap requires the configured exact frontend Origin. Every new guest has a distinct unguessable owner ID. Existing token authentication remains available to operators; no shared anonymous analyst or shared browser token is used. All existing ownership, signed receipts, review gates and strict upload validation remain.

Guest demo/admin routes are denied. Guest storage starts empty, never from fictional seed cases. Limits include40mutations/IP/minute,20public analysis requests/minute, one admitted public analysis at a time,500sessions,10cases per guest,500guest cases globally,8MiB total JSON store and12MiB JSON request bodies (base64 reduces usable media bytes). The reduced128MiB network/correlation worker heap can reject workloads that exceed it; it does not change detection thresholds or silently truncate evidence. Export existing reports when capacity is reached. An expired rate bucket is reclaimed.

`/tmp/veritas-public/investigations.json` is intentionally separate from private analyst stores. It is single-writer and **ephemeral**. Sessions expire after8hours or a server restart; there is no account recovery or cross-browser access. The interface warns visitors to download reports. No promise of durable case storage is made. Uploaded originals are processed but not archived as original evidence. An external durable database/object store and an explicit repository adapter would be required for reliable recovery; they are not implemented by merely setting a URL. [Render free Postgres](https://render.com/docs/free) expires after30days and is not a durable long-term substitute. A separately provisioned free external database would need credentials, schema/migration, owner-isolation and backup testing before claiming persistence.

## Minimal manual provider setup

1. **Vercel access:** approve the connector's team-access consent link when provided. Do not upgrade the account or start a Pro trial. Verify Hobby eligibility and caps in the [current plan documentation](https://vercel.com/docs/plans/hobby). If Git organization linking is restricted for the actual account, use an explicitly scoped prebuilt/static upload; do not purchase a plan or switch to an unrelated team.
2. Create a new Vercel project for this deployment branch, leaving existing projects unchanged. Framework **Other** (`framework:null` in `vercel.json`); install `npm ci`; build `npm run build:vercel`. No output-directory override is needed: the generated `.vercel/output/config.json` uses [Build Output APIv3](https://vercel.com/docs/build-output-api). Copy the actual assigned production HTTPS origin from Project Settings→Domains. Do not guess a URL. Production must be public without Vercel visitor authentication. Preview protection is separate.
3. In Render choose **New→Blueprint**, connect `CyberShieldTeam/Deepfakedet`, branch `codex/free-public-cloud-deployment`, and `render.yaml`. Review **both services are Free**; do not attach paid disks. Supply `VERITAS_PUBLIC_ORIGIN` as the exact actual Vercel production origin, without a trailing slash. The Blueprint generates the private Python token and references the actual media service's `RENDER_EXTERNAL_URL`; no guessed endpoint or hardcoded credential is required.
4. Wait for both builds and health checks. Copy the actual `veritas-api-free` service HTTPS origin from its dashboard. Set **Vercel→Environment Variables→Production** `VERITAS_BACKEND_ORIGIN` to that actual Render origin. No path, credentials or query parameters. The build deliberately fails if this value is absent/invalid, rather than publishing a frontend-only success. Redeploy the frontend from the same reviewed commit.
5. If required, enter `APP_GEMINI_API_KEY` and optional `GEMINI_MODEL` under **Render backend→Environment** only. Use a free-tier/unbilled provider configuration; exhausted quota remains unavailable. The supported runtime variable is **APP_GEMINI_API_KEY**, not a frontend `VITE_` variable. Standalone runtime `GEMINI_API_KEY` is intentionally not consumed by this application; an existing local `.env` fallback is not a production secret configuration. Add optional `GOOGLE_FACT_CHECK_API_KEY` there only if available. Never paste secrets into this repository, chat logs, Vercel frontend build variables or source URLs.
6. Test backend `/api/health` and media `/health`; an unauthenticated media analysis request must return401. Test the Vercel URL in a fresh browser: no login, guest banner, real uploads/measurements, Wikipedia citations, network analysis, save, correlate and report. Open a second fresh browser and verify the first case/report is inaccessible. Inspect service logs/RSS and gateway limits. Do not declare success from health alone.

Only these essential values require operator input: exact Vercel production origin, actual Render backend origin, and optional provider credentials. The shared Python token is generated and wired by the Blueprint. Never copy the local private analyst store to the public service.
