# Future forensic capabilities — 2026-11-15

Feasibility review only: none of the heavyweight dependencies below were installed or
benchmarked in this slice. Compute descriptions are planning estimates, not measured
hardware minimums. Code, checkpoint, upstream data and service terms must be reviewed
separately. Implementation counts do not demonstrate independence or detection accuracy.

| Capability and scientific purpose | Available implementation / compute | License or access position | Validation data and limitations | Evidence independence / decision |
| --- | --- | --- | --- | --- |
| Camera PRNU: source-device fingerprint matching and spatial consistency | [Research implementation](https://github.com/pkorus/multiscale-prnu); reference-noise estimation and aligned correlation, CPU feasible but full-resolution references and residual maps are memory intensive | Dataset/toolbox/third-party component terms require verification; no blanket license grant established here | Authorized same-device and different-device originals, multiple devices/scenes, controlled crops/recompression/denoising and known edits. Source references and alignment are required; weak/missing traces cannot identify AI | Potentially different physical acquisition evidence from a classifier, but only with a genuine reference fingerprint. Current Gaussian residual is not PRNU. Planned |
| RAFT: more capable optical-flow estimation | [Torchvision RAFT](https://docs.pytorch.org/vision/stable/models/raft.html), small/large variants; correlation volumes and resolution increase memory cost, GPU often practical for throughput; no local latency/VRAM measurement | [Original implementation BSD-3-Clause](https://github.com/princeton-vl/RAFT/blob/master/LICENSE); verify selected distributed weights and training-data terms separately | Flow ground truth such as Sintel/KITTI under their terms plus licensed authentic/manipulated video. Measure flow error, runtime, memory and added diagnostic value over Farneback; cuts/occlusion/lighting remain confounds | Same motion evidence family as Farneback, not an independent forgery detector. Deferred until a benchmark shows a material benefit |
| rPPG: physiological color-change signal estimation | [pyVHR](https://github.com/phuselab/pyVHR); classical CPU methods or heavier learned variants; requires sufficiently long, visible skin video and signal-quality gates | Publisher specifies GPL-3.0; review distribution implications and each dataset's participant/access terms | Consented pulse-reference recordings (e.g. appropriately licensed UBFC/PURE subsets) plus disjoint real/manipulated identities, skin tones, illumination, motion, codecs and frame rates. A failed pulse estimate must abstain; generated video may also reproduce periodic changes | Potential physiological evidence but overlaps visual/codec artifacts and lacks universal authenticity guarantees. Planned, no pulse-based verdict |
| MediaPipe facial geometry: landmark/pose continuity | [Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker); CPU/mobile-capable modes with additional model asset, frame/face caps needed; local runtime not measured | [Framework Apache-2.0](https://github.com/google-ai-edge/mediapipe/blob/master/LICENSE); review exact model bundle/card and third-party notices before redistribution | Authorized pose/occlusion/expression and manipulated-face videos, with identity-separated evaluation. Landmark error and quality gates before temporal interpretation. Mesh consistency does not reconstruct or prove physically correct scene lighting | Additional geometry beyond box tracks, partly correlated with face detector/optical flow. Planned |
| DIRE: diffusion reconstruction-error representation plus trained detection | [Authors' implementation](https://github.com/ZhendongWang6/DIRE); diffusion inversion/reconstruction and classifier checkpoints, substantially heavier than current CPU observations; provisioned GPU experiment likely needed, no resource claim measured here | Bundled guided-diffusion component has MIT terms; full detector/checkpoint/data redistribution rights not established by that fact. Repository is archived | Independent camera and diverse diffusion/GAN/edit samples, matched encoding and training-overlap audit; robustness against resizing/noise/recompression. A low scalar reconstruction error is not near-certain proof of generation | Different representation, but generator/reconstruction-model dependencies and possible correlated dataset shortcuts. Deferred under current image-search stopping gate |
| Additional pretrained deepfake classifiers | Existing pinned ViT/community/SDXL and separate face-crop adapters already have exploratory records. Any additional checkpoint needs reproducible preprocessing, known labels, and measured resource admission | Model-specific: Community MIT, Dima Apache-2.0, SDXL CC-BY-NC-3.0; no automatic deployment/license approval for a new checkpoint | Current development images have source and resolution/compression confounds. New source/identity/generator-disjoint data and explicit per-task licenses required; FaceForensics++/DFDC are not general-image-generation substitutes | Correlated errors are likely; voting does not establish calibration or independence. No new search/model integrated |
| SynthID: supported invisible watermark detection | [Official detector description](https://deepmind.google/models/synthid/) provides an accessible detection product; public UI access does not prove a supported server API contract or project entitlement | Proprietary provider terms; no authenticated scanning API request or entitlement was validated here; costs/limits not established | Authorized marked/unmarked samples from supported generators and partners, edits, crops/screenshots and recompressions. Verify exact coverage and false-positive/negative behavior | Potentially distinct watermark evidence, with provider coverage bias. An absent watermark is inconclusive. No adapter or external upload |
| Truepic: signed capture/provenance verification and post-capture processing | [Official Lens API documentation](https://vision.truepic.dev/docs/lens-api) describes JSON credential/capture verification services; actual deployment authentication and permissions remain unverified | Commercial/provider agreement and access required; no successful authenticated call, quota or license entitlement established in this project | Authorized native signed captures, altered/unsigned media and supported formats, with expected certificate/claim states. Device/claim trust and factual event truth differ | Overlaps C2PA validation; trusted acquisition assertions may add evidence when available. Do not count the same signature twice. No adapter or external upload |

Next research should demonstrate *incremental* value on a controlled independent corpus
before integration. A method must expose unavailable, ineligible and failed states;
it must never map absence of a pulse, fingerprint, watermark or credential to a fake
label. No live user media was sent to any vendor during this work.
