# Original-image provenance inspection

Status: partial implementation. Images up to 8 MB send original bytes separately from the browser's resized analysis preview. The Python service uses pinned `c2pa-python==0.39.0` to read the original JPEG, PNG, or WebP and reports the SDK's validation state as `absent`, `valid`, `trusted`, `invalid`, `unknown`, or `unavailable`. Only a structured `stds.schema-org.CreativeWork` `digitalSourceType` in a valid/trusted active manifest can set `aiDeclaration`. The result is displayed separately from image inference and does not change the verdict.

Basic EXIF presence and the Software tag currently come from Pillow. This is not full ExifTool/XMP extraction. Browser byte-string hints are still explicitly unverified and have no provenance scoring effect. A missing manifest or EXIF tag proves nothing about capture or generation. `valid` means no validation error was reported; `trusted` additionally depends on the SDK's trust configuration. Neither proves the depicted event is true.

The CC0 headshot returned `absent` through the real SDK and live Express-to-Python upload. Tests for structured declarations and invalid states use mocked manifest JSON; no real signed or tampered fixture has been verified yet. Next work: real signed/tampered fixtures, explicit trust anchors, signer and claim details, ExifTool extraction, original-file upload limits beyond 8 MB, and server-side jobs. See [official SDK usage](https://github.com/contentauth/c2pa-python/blob/main/docs/usage.md) and [manifest validation guidance](https://opensource.contentauthenticity.org/docs/manifest/reading/manifest-validation/).
